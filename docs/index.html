Docs

JetScheme is a small Scheme, close to R7RS-small: lexical scope, first-class functions, and proper tail calls. Deep tail recursion runs in constant stack space. The forms are quote, define, lambda, if, begin, let, let*, letrec, letrec* (plus named let), set!, and, or, cond with else, when, unless, quasiquote, and include, which reads in another source file. apply calls a procedure with an argument list you build at runtime.

(define (make-counter)
  (let ((n 0))
    (lambda ()
      (set! n (+ n 1))
      n)))

(define a (make-counter))
(define b (make-counter))

(displayn (list (a) (a) (b)))                    ; prints (1 2 1) — b kept its own n

All numbers are 64-bit doubles. exact? and integer? answer #t for every integral value.

Strings are immutable and byte-level UTF-8. string-length and string-ref are byte-indexed, and comparison sorts by codepoint. Case conversion and character classes cover ASCII.

ref and setf! are generic accessors. (ref v i) reads and (setf! v i x) stores x at key i in v. Vectors, strings, bytevectors, and tuples take an integer index; structs take a field name; hashsets and hashmaps take any legal key:

(define v (vector 10 20 30))
(ref v 0)                                        ; => 10   (vector-ref)
(setf! v 0 99)                                   ; vector-set!
(ref v 0)                                        ; => 99

(define pt (point 3 4))                          ; a point struct
(ref pt 'x)                                      ; => 3    (struct field read)
(setf! pt 'x 10)                                 ; struct field mutation

(define m (hashmap 'a 1))                        ; one key, one value
(setf! m 'b 2)                                   ; insert or overwrite
(ref m 'b)                                       ; => 2    (any legal key)

Numbers

+ - * /, quotient, remainder, modulo, abs, square, expt, sqrt, exp, log, sin, cos, tan, asin, acos, atan, floor, ceiling, truncate, round, min, max, and random, which takes no arguments. random-seed reseeds it from the OS.

Comparisons = < <= > >= and predicates zero?, positive?, negative?, even?, odd?, number?. Convert with number->string and string->number. Bitwise ops — bitwise-and, bitwise-ior, bitwise-xor, bitwise-not, arithmetic-shift — operate on integral doubles.

Pairs & lists

cons, car, cdr, set-car!, set-cdr!, pair?, null?, list, list?, the caar…cddddr combinations, and the named accessors first through fifth and rest.

List operations: length, append, reverse, take, drop, last, concatenate, map, for-each, filter, fold, fold-right, reduce-right, and the association-list lookups assq, assv, assoc.

(define (sum xs)
  (let loop ((xs xs) (total 0))                  ; named let — loops via tail call
    (if (null? xs)
        total
        (loop (cdr xs) (+ total (car xs))))))

(displayn (sum '(1 2 3 4 5)))                    ; prints 15

Strings & characters

string, make-string, string-append, substring, string-copy, string-length; index with ref. Comparisons are case-sensitive (string=?, string<?, …) or case-insensitive (string-ci=?, …). There are also string-upcase, string-downcase, and conversions between strings, lists, and vectors (string->list, list->string, string->vector, vector->string).

Characters: char->integer, integer->char, comparisons (char=?, char-ci=?, …), predicates char-alphabetic?, char-numeric?, char-whitespace?, char-upper-case?, char-lower-case?, plus char-upcase, char-downcase, and digit-value. Named literals: #\space, #\newline, #\tab, #\return, #\null, #\escape, #\backspace, #\delete.

Vectors & bytevectors

vector, make-vector, vector?, vector-length; bytevector, make-bytevector, bytevector?, bytevector-length, bytevector-copy, bytevector-copy!, bytevector-append, plus vector-ref, vector-set!, bytevector-u8-ref, and bytevector-u8-set!. As literals: #(1 2 3) and #u8(1 2 3).

Structs

struct, isa?. Every call to struct makes a new type. Two types with the same name and fields are still different.

(define point (struct 'point '(x y)))            ; create a fresh type
(define p (point 3 4))                           ; call the type to construct
(isa? p point)                                   ; => #t
(ref p 'x)                                       ; => 3
(setf! p 'x 10)                                  ; mutate field

Tuples

tuple. Constructs an immutable, fixed-size tuple, indexed with ref. The literal form is #tuple(...), and its elements are data rather than expressions.

(define t (tuple 'a 'b 'c))
(isa? t tuple)                                   ; => #t
(ref t 1)                                        ; => b
(equal? t #tuple(a b c))                         ; => #t   the same tuple
`#tuple(a ,(+ 1 1))                              ; => #tuple(a 2)   a template

Equality & symbols

eq? compares identity, eqv? compares identity and numbers by value, and equal? compares structures recursively. There are also the type-specific predicates boolean=?, symbol=?, and string=?. Symbols convert with symbol->string and string->symbol, and there are symbol? and procedure?.

(eq? 'a 'a)                                      ; => #t   same symbol
(eq? (string->symbol "a") 'a)                    ; => #t   same symbol from a string
(eqv? 2 2)                                       ; => #t   numbers compare by value
(equal? '(1 2) '(1 2))                           ; => #t   same contents
(eq? '(1 2) '(1 2))                              ; => #f   different pairs

Hash tables & sets

hashset, hashmap, hashset?, hashmap?. ref on a hashset tells you whether the element is there, and on a hashmap it raises an error when the key is absent. setf! sets a hashmap key to any value, and a hashset element to #t.

The literal forms are #hashset(...) and #hashmap(...). #hashmap takes a key, then its value, and so on.

(define m (hashmap 'a 1 'b 2))
(ref m 'a)                                       ; => 1
(setf! m 'c 3)                                   ; insert or overwrite
(ref (hashset 'a) 'b)                            ; => #f
(ref #hashmap(a 1 b 2) 'b)                       ; => 2
(ref #hashset(a b) 'a)                           ; => #t

Keys are immutable. Legal keys are numbers, booleans, characters, the empty list, the eof object, symbols, strings, and tuples whose elements are themselves legal keys. Anything mutable, or holding something mutable, is rejected with a runtime error: pairs, vectors, bytevectors, structs, procedures, ports, and the tables themselves. Duplicate keys collapse as a table is built, and the last value wins.

I/O & files

display prints a value for a person to read. write prints it in the literal forms above, so read parses that output back into an equal value. Both print to stdout. newline prints a newline, and displayn is display followed by a newline. read takes one datum at a time from an input port:

(define p (open-input-file "data.ss"))
(define a (read p))                              ; first datum
(define b (read p))                              ; second datum
(close-input-port p)

To read and write a file one character at a time there are open-input-file, open-output-file, read-char, write-char, close-input-port, and close-output-port, plus the predicates input-port?, output-port?, and eof-object?.

Running programs

argv is a vector of the script's command-line arguments, with the binary and script path already stripped. exit ends the process. The prelude loads from lib/prelude.ss beside the binary; set JET_PRELUDE to another prelude file, or pass --no-prelude to skip it.

jet run (or just jet file.ss) compiles and runs a program. jet compile writes bytecode to stdout, jet exec runs it, and jet disasm disassembles either source or bytecode. --no-inline, --no-lift-lambdas, and --no-specialize-ops switch off individual optimizations. Debug builds add --trace for an opcode-by-opcode execution trace.

($check expr) reports the source position and fails when expr is false. $file, $line, and $col give you that file, line, and column.

Impl

JetScheme is built on techniques described in:

  • Tail-threaded dispatch (Bell, 1973) — each opcode is its own small function, and each function ends by tail-calling the next one directly. There is no central dispatch loop and no callee-save spills between opcodes, so hot VM state stays in registers across the whole run.
  • Inline caching (Deutsch & Schiffman, 1984) — the first time through a call site, the slow path patches the opcode in place to point at a specialized fast version of itself. Later passes through that site skip the lookup, key compare, and type check entirely.
  • Flat closures (Dybvig, 1987) — captures live in an inline array on the closure. Immutable ones are copied by value; a capture that is both mutated and shared gets a heap indirection.
  • A-normal form (Flanagan et al., 1993) — every operand is a variable or a literal, and every intermediate result gets an explicit name. The later passes — inlining, register allocation, instruction selection — then rewrite one flat shape instead of arbitrary nested trees.
  • NaN-boxing (Gudeman, 1993) — every value fits in 8 bytes. Numbers are raw doubles, while immediates and tagged heap pointers hide in the IEEE 754 quiet-NaN payload. Type tests are cheap bit ops, and any value passes in a single register.
  • Superinstructions (Proebsting, 1995) — common back-to-back opcode pairs are emitted as one fused opcode. That is a single chain step instead of two, and the body can skip the intermediate register move.
  • Opcode replication for inline caches (Ertl & Gregg, 2003) — each cached opcode has several near-identical copies that rotate per call site. Distinct sites then land on distinct branch-target-predictor entries instead of all colliding on one.
